# 芝公园、东京塔、增上寺与大门地图巡检

## 实车通行

- 通过正常地标按钮、鼠标转向、F 进车、W 前进、S 倒车，在三解脱门前从路面驶入具有公园覆盖标记的草地。去程 34.05 米，回程距起点 0.43 米。道路与草地上的四轮实测接触位置距局部地表均小于 1 毫米。终点四轮采到的公园覆盖值为 255、255、246、255（满值 255）。[车辆驶入草地的游戏画面](复核/驶入公园草地.png)
- 从大门路口向北行驶 99.29 米，通过旧版裁切线。两条车道共检查 402 个实际三角面高程点，其中 116 个位于原精模边界以外。这次正常加速行驶的 6 秒采样为 60.00 FPS。[穿过大门北侧旧边界的游戏画面](复核/大门向北通行.png)
- 按整车轮廓对 158 段主次干道及连接线完成 10,156 次米级横断面检查，每个断面都有能容纳整车的位置。对港区役所连廊及两条带顶通道另外做了连续扫掠。车身会与真实柱脚、墙体、树干和地铁井口接触。

## 返工记录

| 巡检顺序 | 暴露的问题 | 修改与复核 |
| --- | --- | --- |
| 1 | 低清立面缺少近景层次，部分平屋顶的相邻标高被归到同一层 | 分离实拍外墙与四类米制窗格，给街铺和办公入口加入室内纵深。减小屋顶分层容差，并以构件的完整底面逐件复验。 |
| 2 | 新大气着色与原材质的着色变量冲突，部分表面绘制缺失 | 修正着色器并在实际 Chrome 重拍日、暮、夜三个时段。 |
| 3 | 塔下机位被邻楼遮住，塔基入口与站口在近处难以辨认 | 按底座方向重做前厅、雨棚和塔脚连接件。三个地铁入口切开铺装及地形，补上楼梯踏鼻、扶手和壁灯。重新选择能看见实体接合处的机位。 |
| 4 | 车辆受车道中心线距离限制，穿楼道路及区役所连廊被建筑外壳封住 | 从实际渲染的模型截取车身高度范围内的实体。切开有测绘依据的三处通道，并实际往返公园草地。 |
| 5 | 古川被航拍地面盖住，个别树根落入水面，桥底缺少尺度参照 | 按国土地理院水域重建河面，纠正三个树位。桥灯逐盏核对测绘板底，最低灯下净空为 4.543 米。 |
| 6 | 轮胎比地面高约 14 厘米，切换视角时绘制峰值曾到 240 | 四轮独立取高。预生成三套环境反射，共享路口铭牌和灯组的绘制批次，并复查切换、步行和实车路线。 |
| 7 | 分区俯瞰时，大门路口以北两条车道在资料边缘被切成圆头 | 用原始道路中心线重做接缝的沥青和步道，周边路面与背景地形作布尔分割。精模边界外保留 74 米通行带。 |
| 8 | 桥面裁口产生了一段横向护岸，遮断了桥下水面 | 护壁改沿实际岸线，桥下补齐 662.82 平方米较低标高的连续水面。再次查看桥底和两岸的原图。 |
| 9 | 初夜首次驾车转弯时，建筑贴图集中上传，最慢的一次约 59 毫秒，整段实测 57.2 FPS | 将立面贴图上传和着色程序准备移入地图载入阶段，树干和树冠只提交可见或会投影的实例。同一路线复测 60.0 FPS，P95 为 16.8 毫秒。 |

## 模型与材质

- 核心区 568,358.64 平方米。636 栋建筑共检查 20,743 段基础边，最小埋深 3.5 米。633 栋常规建筑的屋顶投影未检出缺口。另核查了两座寺门的开口和塔身的开放钢架。
- 地面拓扑实测重叠面积 0 平方米，15,503 段路缘中侵入车道的为 0 段。135 处过街带与停止线冲突 0 处。247 处道路井盖和雨水口与沥青共享边线。
- 231 个沿街开间均检查朝向、车道、盲道和站口净空。1,106 个屋顶构件分布在 153 栋合适建筑上。540 个树位中落入车道、建筑或水面的各为 0。
- 在浏览器实例矩阵中复查了 758 个信号灯、灯杆、护栏柱或龙门架杆脚。与布局坐标的最大三维偏差为 0.000032 米。
- 在 Blender 4.5.3 重新打开工程，确认 87 张图像已内嵌并使用相对路径，逐组展开实例后完成 Cycles 渲染。[Blender 实际渲染](复核/Blender实渲.jpg)
